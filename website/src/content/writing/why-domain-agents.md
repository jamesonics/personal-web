通用大模型擅长回答广泛的问题，但真实工程任务往往包含大量隐含规则：术语体系、设计边界、经验公式、仿真工具和验证流程。它们并不只需要一个更长的 Prompt，而需要一个能够理解任务、查找证据、调用工具、记录中间状态并接受工程师复核的系统。

这也是我把研究重点放在 **垂类智能体（Domain-specific Agent）** 上的原因。

## 从“回答问题”走向“完成任务”

我希望构建的系统不止是对话界面，而是一条可以被检查和复现的工作链路：

1. 理解工程需求及约束；
2. 从专业文档中检索可引用的证据；
3. 调用计算、仿真或数据处理工具；
4. 在关键节点请求人工确认；
5. 输出方案，同时保留推理依据和执行记录。

## 为什么选择叶轮机械

叶轮机械设计知识密集、工具链长，并且非常依赖领域经验。它既能检验 RAG 是否真的理解专业资料，也能检验 Agent 是否能够在复杂约束下稳定调用工具。

我的当前工作包括文档知识库、检索评测、MCP 工具接入和多 Agent 协作。接下来，我会持续记录系统从 Demo 走向可靠研究工具的过程。
