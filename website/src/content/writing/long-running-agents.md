长时间运行的 Coding Agent 面临两个常见问题：上下文会被逐渐稀释，Agent 也容易把“完成了局部改动”误判成“完成了整个项目”。

## 1. 把状态写进仓库

任务目标、已完成项、验证命令和下一步不应该只存在于对话中。一个简洁的进度文件可以让新的会话快速恢复上下文。

## 2. 每次只交付一个可验证增量

“大改整个系统”很难验证。更好的方法是把任务拆成可以单独构建、测试或在浏览器中检查的功能块。

## 3. 完成必须有证据

代码改完不等于任务完成。构建输出、自动化测试、浏览器行为和最终产物都应成为验收证据。

这些原则同样适用于科研自动化：重要的不是 Agent 能连续运行多久，而是它能否在长时间运行中持续保持任务边界和可验证性。
