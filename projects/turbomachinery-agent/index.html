01

PROJECT POSITIONING

不是一个“会聊天”的助手，
而是一条可验证的工程设计链路

传统流程的断点

  • 设计目标、专业知识和仿真工具分散在不同系统中
  • 高度依赖工程师经验与重复试算，过程难以复用
  • 脚本只能连接固定步骤，无法根据反馈动态调整
  • 结果缺少统一证据链，失败原因难以定位

我的研究目标

通过 LangGraph 管理任务状态与条件分支，以 RAG 提供专业知识依据，以 MCP 接入工程工具，并将每次规划、检索、调用和结果保留为可检查记录。

让“需求理解 → 方案执行 → 结果验证 → 报告沉淀”成为一条可以复现和持续迭代的工作流。
